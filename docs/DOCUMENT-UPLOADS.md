# Document and data uploads

Uploads are private to the selected estate. The **Document & data imports** permission controls view/add. Publishing survey measurements additionally requires **Geospatial Analysis → add**; creating a raster overlay requires **Map workspace → add**. Existing block master and financial records are never silently overwritten by an inferred PDF table.

Supported extraction: searchable PDF text/tables, scanned PDF/image OCR, PNG/JPEG/WebP/TIFF, XLSX/XLS, UTF-8 CSV/TSV. Excel formulas remain source text (XLS cached values); no macros or instructions are executed. CSV delimiter detection supports comma, semicolon, tab and pipe. Every worksheet, page and source row retains its identity. Geographic boundary uploads continue through the WGS 84 GeoJSON option. Convert other GIS containers to GeoJSON using QGIS before uploading; no arbitrary GIS drivers run on uploaded files.

Flow: upload → durable background extraction → paginated review → keep dataset or explicitly map one source table to Geospatial Analysis. The latter links only exact, unambiguous estate block references. Invalid numbers, unmatched references and area differences carry Highlight flags. All automatically extracted rows retain a review flag. Raw fields remain available in Data → Imported data. PDF excerpts are source material, not AI agronomic recommendations. Reports keep source and upload dates, original files and a suggested annual survey target. PDF pages and images can become dated map overlays after supplying whole-image geographic bounds; margins/legends must be accounted for or removed in a georeferenced export.

Collections: MappingDocumentImport, MappingDocumentRow, plus published MappingGeospatialReport/Row and imagery MappingAsset. Sources and extracted NDJSON are stored under `data/estates/<estateId>/documents/<importId>/`. Estate archives include both collections and these files. SHA-256 duplicate detection is per estate; identical files reuse the original import. Annual surveys with changed content create new imports/reports. Failed extraction can be retried; publication is idempotent per import.

Limits: 200 MB per file, two receiving uploads, queue of 20, one extractor per process with a MongoDB lease, 8-minute extraction timeout, 200 PDF pages, 50 XLSX sheets, 100,000 extracted rows, 200 columns, 200,000 characters per cell, 512 MB extracted output, 500 MB expanded XLSX. Row review uses indexed sequence cursors and 25-row pages. Queue leases recover after interruption; failed jobs retain original files. The system does not claim to infer precise boundaries from an unreferenced PDF or recover unknown financial units automatically.

Runtime: Python 3 with pdfplumber 0.11.7, openpyxl 3.1.5, xlrd 2.0.2 and Pillow 11.3.0; Poppler and Tesseract executables. Set `DOCUMENT_IMPORT_PYTHON` to the private environment executable. Malaysia runtime: `/home/deploy_mapping/app/tools/document-import/bin/python`. Dependencies run offline; extraction does not transmit source files to a third-party AI service.
